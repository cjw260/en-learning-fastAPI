# P05：支付、Socket.IO 与后台任务

状态：`IN_PROGRESS`

## 启动条件

P04 完成并推送；新的执行重新加载 skill 和 framework parity；阶段锁为 P05。

## 目标与外部效果

可靠迁移支付创建/回调、支付成功实时通知以及每日学习摘要；重复、并发、进程重启和依赖故障不会造成重复权益或静默丢失。

## 实现步骤

1. 支付创建从数据库读取课程、价格和标题，生成唯一 outTradeNo；忽略客户端金额作为事实来源。
2. 回调先按支付宝要求对原始参数验签，再校验 app/商户、订单、金额、状态和用户/课程关系。
3. 以订单状态机和唯一约束处理重复/乱序通知，在单事务内更新订单与课程权益。
4. 事务提交后写可靠通知/事件记录，再尝试 Socket.IO emit；即时失败可重放。
5. 用 `python-socketio` 保持 `paymentSuccess` 兼容，JWT 绑定用户房间，Redis manager 支持多实例。
6. 将每日摘要和邮件发送迁入独立 worker/调度器，增加唯一任务键、分布式锁、超时、退避、最大重试和失败记录。
7. 对 Redis、SMTP、支付宝和 Socket 故障进行注入；证明支付数据库事实不被通知失败破坏。
8. 增加脱敏审计日志和人工补偿/重放命令。

## 验收标准

- [x] 客户端不能伪造金额、课程或用户。
- [x] 有效/无效签名、重复、乱序、金额不符、未知订单测试通过。
- [x] 同一订单只授予一次权益，事务边界正确。
- [x] Socket.IO 认证、房间、重连、多标签页和 Redis 跨实例通过。
- [x] `paymentSuccess` 事件名和主要载荷兼容。
- [x] worker 重启、重复投递、调度锁、重试和失败记录可验证。
- [x] 通知失败后可通过 API 查询和补偿达到最终一致。
- [x] 敏感支付/邮件数据未写入普通日志。

## 回退

支付整体切回 NestJS并暂停新 worker，避免双写/双消费；保留审计和事件重放数据。
