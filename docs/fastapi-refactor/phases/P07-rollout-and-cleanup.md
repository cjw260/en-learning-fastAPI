# P07：灰度上线与旧后端清理

状态：`NOT_STARTED`

## 启动条件

P06 完成并推送；用户明确授权生产部署；新的执行重新加载 skill；阶段锁为 P07。

## 目标与外部效果

使用 systemd + Uvicorn 旁路部署 FastAPI，先 AI 后 Core 灰度切流，在可观察和可回退前提下完成生产替换；稳定期和用户确认前不删除 NestJS。

## 实现步骤

1. 备份 PostgreSQL 并实际验证恢复；保存 Nginx、PM2、环境和部署脚本配置。
2. 建立非 root systemd unit：Core、AI、worker、scheduler；配置环境文件、重启、超时、文件句柄和日志。
3. 旁路端口启动，执行 migration、ready、seed 只读校验和内部冒烟，不占旧端口。
4. 只灰度 `/ai/`，观察锁定窗口和阈值；通过后再单独灰度 `/api/`。
5. 验证 SSE、Socket.IO、多实例、worker、数据库连接、Redis、MinIO、邮件和真实小额支付。
6. 触发回退阈值时恢复 Nginx upstream、暂停新 worker，记录证据并处理切换窗口数据。
7. 全量稳定观察期后，由用户确认是否停止 PM2 NestJS；先归档再讨论代码清理。
8. 更新正式部署、运维、监控、备份/恢复和故障手册。

## 验收标准

- [ ] 获得本阶段生产授权，备份可恢复，回退演练成功。
- [ ] systemd 生命周期、权限、日志和开机启动正常。
- [ ] AI/Core 分开灰度且每步有时间、指标和结果。
- [ ] 错误率、P95、连接池、Redis、SSE、Socket、支付、worker 在锁定阈值内。
- [ ] 真实小额支付和重复回调闭环通过。
- [ ] 回退可在目标时间内恢复旧服务且不丢关键数据。
- [ ] 用户确认前未删除旧服务、旧仓库或历史。
- [ ] 运维文档、审查、复测、提交和推送完成。

## 回退

恢复保存的 Nginx upstream，启动 PM2 NestJS，暂停 FastAPI worker 防止双消费；按审计记录处理窗口数据，不盲目回滚数据库。
